# JF 案例叙事结构与板块框架

在 `1.JF主线框架与设计重点.md` 确认了案例定位和两个深潜模块之后，这份文档定下案例整体怎么讲——参照 `总/项目叙事方法参考.md` 的六种叙事方法，以及 PR 案例（`1.pr项目/`）已验证的叙事原则，但不直接照搬 PR 的结构。

## 1. 叙事方法选择

JF 的定位陈述（"问题→由问题催生的设计决策"，而非"调研了哪些东西"）对应**方法四·决策驱动日志**，而不是 PR 用的**方法三·单线深挖+佐证**——JF 和 PR 的核心差异就在于"做了真实的设计取舍"而非"整合打通了很多系统"。

JF 有两个值得深挖的模块，证据来源不同但强度对称：
- **History**：真实外部证据——5 家竞品（Jira/GitHub/Notion/Whimsical/Zendesk）历史记录功能对比调研 + Insights & opportunities 提炼。
- **Editor/Blockstruktur**：~~最初以为只有内部规则推导型证据，没有可用性测试数据~~ **已确认**：产品 beta 上线后，专业客服部门收集了真实用户反馈，覆盖主页面、meeting 详情（基础信息/参与者/纪要列表）、editor 页面等——不止 Editor/Blockstruktur，是当时整个产品范围。反馈已有文字整理但分散，需要筛选出有意义且不涉密的条目才能用作案例素材。History 因为是 beta 之后才上线的功能，**可能没有**对应的客服反馈，待确认。

结论：整体框架用方法四（决策驱动）做骨架，两个深潜板块内部各自借用方法三（有真实证据支撑的问题→过程→决策）的呈现方式，证据来源不同（客服反馈 vs 竞品调研）。

## 2. 已确认的结构性决定

- **两个深潜顺序：Editor/Blockstruktur 在前，History 在后**——Editor/Blockstruktur 是"地基性"决策（把 Excel 心智模型转成层级块结构），History 要解决的"信任/可追溯"问题是结构化编辑带来的衍生问题，因果顺序更自然。
- **"系统一致性"不设独立重点板块**，只在深潜板块结尾或结果板块里简单提一句（JF 虽大量原创设计，仍与产品整体风格保持一致），不像 PR 案例的"系统性思维佐证"那样单独展开。

## 3. 板块结构

| # | 板块 | 叙事任务 | 叙事方法 | 证据来源 |
|---|---|---|---|---|
| 1 | Hero / 定位 | 一句话说清 JF 是什么、用户角色，预告"这是个决策密集型案例" | — | 框架文档定位陈述 |
| 2 | 背景与挑战（原规划称"问题——Excel 路径依赖"） | 讲清监理/施工场景用户为什么困在 Excel 里，这个习惯具体是什么，为什么是学习曲线问题而非数据迁移问题 | 方法一（问题先行），为方法四铺垫 | Workflow FigJam、框架文档问题陈述 |
| 3 | 设计决策总览——从习惯到结构 | 桥接段落：点出核心设计赌注（Excel 心智模型→受约束的结构化编辑器），预告分裂出两条子线 | 方法四主脊 | 框架文档因果链表述；客户手动维护多年的真实会议纪要范例（图例规则 + 实际填写内容，已脱敏）——**已确认（2026-09-19）改放此板块**，因为连接句需要 Blockstruktur 上下文，这个铺垫在板块2还不成立 |
| 4 | 深潜一——Editor / Blockstruktur | 层级块结构的取舍：考虑过哪些方案、为什么选了 Überschrift/Protokollpunkt/Absatz/Bild + 嵌套编号规则、如何与 Notion/Zendesk 等通用工具形成差异化。用筛选后的客服反馈作证据 | 方法四为主，借方法三证据呈现方式 | Figma 截图 + 筛选后的客服反馈引语（**已确认（2026-09-18）部分落地**：Absatz 多责任人分配未被发现这条已用作证据并上线，含优化前/优化后占位图；"为什么选定这几种块类型"的设计推理素材仍缺，板块4还不是完整深潜） |

| 6 | 影响力/结果 & 诚实的待补充 | 已知定性信号；简单一句系统一致性；诚实说明目前无量化使用数据/埋点，未来打算 | 借鉴 PR 的诚实收尾方式 | 框架文档 + 待补埋点方案 |

### 已确认的实施调整（2026-09-19）

- **Sheet 编号对照**：上表里 Hero 是第1行、"背景与挑战"是第2行，但代码里 Hero 不挂 SHEET 编号（对齐 PR 案例做法）——"背景与挑战"是 **SHEET 01**，"设计决策总览"是 **SHEET 02**，"深潜一 Editor/Blockstruktur"是 **SHEET 03**。也就是说，上表的"第 N 行"对应代码里的"SHEET (N-1)"。
- **命名偏离**：第2行原规划叫"问题——Excel 路径依赖"，写文案草稿（doc3）时改名成"背景与挑战"，为了对齐 PR 案例同名板块的命名习惯——内容没变，只是标题换了。
- **证据分配偏离**：原规划把"真实 PDF 示例"分配给第2行（问题），实际拿到客户手动维护的真实范例图后改放进了第3行（决策总览）——用户已确认保留这个偏离，不挪动图片位置（见上表第3行"证据来源"）。

## 4. 仍悬而未决

- **Editor/Blockstruktur 板块要等客服反馈筛选完才能落笔**——需要从分散的文字反馈里筛出有意义、不涉密的条目。**已确认（2026-09-18）部分完成**：客服反馈已筛选出一条（通过 Absatz 分配多责任人未被发现），板块4已用这条反馈起草并上线（含优化前/优化后占位图）；但"为什么最终选定 Überschrift/Protokollpunkt/Absatz/Bild 这几种块类型和嵌套编号规则"的设计推理素材仍然没有，这条待办保持打开，板块4目前还不是完整的深潜。
- **History 是否也有客服反馈待核实**（该功能是 beta 之后才上线的，不确定是否覆盖）。
- **是否有第三个深潜模块**（候选：多人并发编辑冲突处理、纪要状态流转与签署审批、纪要点类型联动规则）——目前结构假设正好两个深潜，若后续确认加第三个，需重新决定是升级成完整深潜还是折进板块3/6做简短提及。
